TypeScript là gì? Tại sao cần học?

🟢 NEWBIE

TypeScript = JavaScript + Hệ thống kiểu dữ liệu (Type System)

TypeScript là ngôn ngữ do Microsoft tạo ra năm 2012 bằng cách thêm "lớp áo giáp" kiểu dữ liệu lên trên JavaScript. Mọi code JavaScript hợp lệ đều là code TypeScript hợp lệ.

So sánh JavaScript vs TypeScript

javascript — Không có kiểu dữ liệu
// JavaScript: Mọi thứ tự do, không ai kiểm soát
let studentName = "Nguyễn Văn A"
studentName = 12345        // CHẠY ĐƯỢC! Nhưng là BUG tiềm ẩn!
studentName = true         // CHẠY ĐƯỢC! Biến đang là chuỗi lại thành boolean

function add(a, b) {
    return a + b
}
add("1", 2)   // Kết quả: "12" (NỐI CHUỖI chứ không phải phép cộng!)
add()          // Kết quả: NaN (Not a Number — Lỗi ngầm!)
typescript — Có kiểu dữ liệu bảo vệ
// TypeScript: Mọi thứ được kiểm soát chặt chẽ
let studentName: string = "Nguyễn Văn A"
studentName = 12345        // ❌ LỖI NGAY! Type 'number' không gán được cho type 'string'

function add(a: number, b: number): number {
    return a + b
}
add("1", 2)   // ❌ LỖI NGAY! Argument '"1"' không phải number
add()          // ❌ LỖI NGAY! Thiếu 2 tham số bắt buộc
add(1, 2)      // ✅ 3 — Chính xác!
💡
Ghi nhớ cốt lõi: TypeScript báo lỗi LÚC BẠN GÕ CODE (trong VS Code, gạch đỏ ngay trước mắt). JavaScript chỉ báo lỗi LÚC CHẠY (mở trình duyệt lên mới thấy lỗi, hoặc tệ hơn là chạy bình thường nhưng ra kết quả sai bét).

TypeScript hoạt động thế nào?

Trình duyệt web KHÔNG hiểu TypeScript. Trước khi chạy, TypeScript phải được dịch (compile) sang JavaScript thuần:

Quy trình biên dịch
// Bạn viết (TypeScript):
const age: number = 25

// Sau khi compile, trình duyệt nhận được (JavaScript):
const age = 25

// Phần ": number" bị XÓA SẠCH sau khi compile!
// TypeScript chỉ tồn tại lúc bạn ngồi gõ code,
// khi chạy thật nó biến mất hoàn toàn.

Các kiểu dữ liệu cơ bản

🟢 NEWBIE

TypeScript có 7 kiểu dữ liệu nguyên thủy (Primitive Types) mà bạn cần nắm vững:

KiểuÝ nghĩaVí dụ
stringChuỗi ký tự (văn bản)"Xin chào", 'Hello'
numberSố (nguyên + thập phân)42, 3.14, -7
booleanĐúng hoặc Saitrue, false
nullGiá trị rỗng (có chủ đích)null
undefinedChưa được gán giá trịundefined
bigintSố cực lớn9007199254740991n
symbolGiá trị duy nhất (hiếm dùng)Symbol("id")
basics.ts — Khai báo biến với kiểu dữ liệu
// ====== CÁCH 1: Khai báo tường minh (Explicit) ======
let fullName: string = "Nguyễn Văn A"
let age: number = 20
let isStudent: boolean = true
let score: number | null = null   // Có thể là số HOẶC null

// ====== CÁCH 2: TypeScript tự suy luận (Type Inference) ======
let city = "Hà Nội"              // TS tự hiểu: city là string
let year = 2024                 // TS tự hiểu: year là number
let isActive = false            // TS tự hiểu: isActive là boolean

// ====== const vs let ======
const PI = 3.14                 // const: Không thể gán lại (hằng số)
let counter = 0                // let: Có thể thay đổi giá trị
counter = 1                    // ✅ OK
// PI = 3.15                   // ❌ LỖI! const không được gán lại

// ====== any — "Tắt" TypeScript (TRÁNH DÙNG!) ======
let data: any = "hello"
data = 42                      // ✅ Nhưng mất hết sự bảo vệ!
data = true                    // ✅ Nguy hiểm: giống viết JavaScript thuần
⚠️
Tránh dùng any bằng mọi giá! Khi bạn khai báo any, TypeScript sẽ "nhắm mắt làm ngơ" và không kiểm tra kiểu dữ liệu nữa. Nếu không biết kiểu gì, hãy dùng unknown thay thế.

Type Inference (Suy luận tự động)

TypeScript rất thông minh, nó có thể tự đoán kiểu dữ liệu. Bạn KHÔNG CẦN phải ghi kiểu ở mọi nơi:

inference.ts
// TypeScript tự suy luận — BẠN KHÔNG CẦN GHI KIỂU
let message = "Xin chào"    // TS tự biết: string
let count = 0              // TS tự biết: number
let items = [1, 2, 3]     // TS tự biết: number[]

// CHỈ ghi kiểu khi TypeScript KHÔNG THỂ TỰ ĐOÁN được:
let result: string | number   // Biến có thể là string HOẶC number
let user: User | null = null  // Khởi tạo null, sau này sẽ gán User

Hàm (Function) trong TypeScript

🟢 NEWBIE

Hàm là nơi bạn sẽ ghi kiểu dữ liệu nhiều nhất. Bạn cần chỉ rõ: tham số đầu vào là gì, và hàm trả về cái gì.

functions.ts — Các cách viết hàm
// ====== 1. Function Declaration ======
function greet(name: string): string {
    return `Xin chào, ${name}!`
}
//           ↑ tham số    ↑ kiểu trả về

// ====== 2. Arrow Function (phổ biến trong React) ======
const add = (a: number, b: number): number => {
    return a + b
}
// Viết gọn (1 dòng return):
const multiply = (a: number, b: number): number => a * b

// ====== 3. Tham số tùy chọn (dấu ?) ======
function createUser(name: string, age?: number): string {
    if (age) { return `${name} - ${age} tuổi` }
    return name
}
createUser("An")       // ✅ OK — age là tùy chọn
createUser("An", 20)  // ✅ OK

// ====== 4. Giá trị mặc định ======
function welcome(name: string, role: string = "student"): string {
    return `${name} (${role})`
}

// ====== 5. Hàm không trả về gì (void) ======
function logMessage(msg: string): void {
    console.log(msg)
}
📌
Quy tắc vàng:
  • Tham số: LUÔN ghi kiểu (vì TS không thể tự suy luận).
  • Kiểu trả về: TS thường tự suy luận được, nhưng ghi ra thì code sẽ rõ ràng hơn.

Object, Interface & Type Alias

🔵 JUNIOR

Đây là chương quan trọng nhất của TypeScript! Trong dự án thực tế, bạn sẽ làm việc với object hầu hết thời gian.

Interface — Bản thiết kế cho Object

interfaces.ts — Khai báo interface
// Khai báo "bản thiết kế" cho một Học sinh
interface Student {
    id: number
    fullName: string
    phoneNumber: string
    grade: number
    isActive: boolean
    email?: string           // Dấu ? = tùy chọn (có thể không có)
}

// Sử dụng interface để tạo object
const student1: Student = {
    id: 1,
    fullName: "Trần Văn B",
    phoneNumber: "0987654321",
    grade: 10,
    isActive: true
    // email không bắt buộc nên bỏ qua được
}

// ❌ LỖI! Thiếu thuộc tính bắt buộc 'grade'
const student2: Student = {
    id: 2, fullName: "Lê Thị C",
    phoneNumber: "0912345678", isActive: true
}

Type Alias — Cách thứ 2 để định nghĩa kiểu

types.ts — type vs interface
// Dùng "type" — Cú pháp hơi khác nhưng tác dụng tương tự
type LoginFormData = {
    phoneNumber: string
    password: string
}

// type còn làm được những thứ interface KHÔNG LÀM ĐƯỢC:
type UserRole = "student" | "teacher" | "admin"   // Union of literals
type ID = string | number                                // Union type
type Coordinate = [number, number]                     // Tuple

Khi nào dùng interface, khi nào dùng type?

Tiêu chíinterfacetype
Mô tả hình dạng object✅ Chuẩn bài✅ Được
Kế thừa / mở rộng (extends)✅ Dễ dàng✅ Dùng &
Union type (A | B)❌ Không được✅ Chuẩn bài
Tuple, Literal, Mapped type❌ Không được✅ Chuẩn bài
Dùng trong React (Props, State)✅ Phổ biến nhất✅ Cũng phổ biến
🎯
Quy tắc đơn giản nhất: Dùng interface khi mô tả hình dạng của object (Props, API response...). Dùng type cho mọi thứ còn lại (union, tuple, computed type...).

Kế thừa Interface (extends)

extends.ts
interface BaseUser {
    id: number
    fullName: string
    phoneNumber: string
}

interface Student extends BaseUser {
    grade: number
    classRoom: string
}

interface Teacher extends BaseUser {
    subject: string
    yearsOfExperience: number
}

// Student sẽ có: id, fullName, phoneNumber + grade, classRoom
const student: Student = {
    id: 1, fullName: "Nguyễn Văn A",
    phoneNumber: "0987654321", grade: 10, classRoom: "10A1"
}

Union, Intersection & Literal Types

🔵 JUNIOR

Union Type — "HOẶC"

union.ts
type ID = string | number
let userId: ID = 123       // ✅ number
userId = "abc-xyz"         // ✅ string

// Ứng dụng thực tế:
type ApiResponse = {
    status: "success" | "error"
    data: string | null
    code: number
}

// Ví dụ trong dự án LMS:
type Score = number | "Chưa có điểm" | "Vắng"

Intersection Type — "VÀ"

intersection.ts
type HasName = { name: string }
type HasAge = { age: number }
type HasRole = { role: "student" | "teacher" }

// Person = phải có CẢ name, CẢ age, CẢ role
type Person = HasName & HasAge & HasRole

const person: Person = { name: "An", age: 20, role: "student" }

Literal Types — Giá trị cụ thể làm kiểu

literal.ts
type Direction = "up" | "down" | "left" | "right"
type HttpMethod = "GET" | "POST" | "PUT" | "DELETE"
type Grade = 10 | 11 | 12

function move(dir: Direction) { /* ... */ }
move("up")     // ✅
// move("diagonal")  // ❌ "diagonal" không phải giá trị hợp lệ!

Type Narrowing & Type Guards

🟣 MID-LEVEL

Khi biến có Union Type, bạn phải "thu hẹp" (narrow) kiểu để xử lý đúng.

narrowing.ts
// ====== typeof Guard ======
function display(value: string | number) {
    if (typeof value === "string") {
        console.log(value.toUpperCase())  // TS biết chắc: string
    } else {
        console.log(value.toFixed(2))     // TS biết chắc: number
    }
}

// ====== Truthiness Guard (Kiểm tra null/undefined) ======
function printName(name: string | null) {
    if (name) {
        console.log(name.toUpperCase())
    }
}

// ====== "in" Guard ======
interface Student { grade: number }
interface Teacher { subject: string }

function getInfo(person: Student | Teacher) {
    if ("grade" in person) {
        console.log(`Học sinh lớp ${person.grade}`)
    } else {
        console.log(`Giáo viên môn ${person.subject}`)
    }
}

// ====== Discriminated Union (Pattern cực mạnh!) ======
interface SuccessResponse { status: "success"; data: string }
interface ErrorResponse { status: "error"; message: string }
type ApiResponse = SuccessResponse | ErrorResponse

function handleResponse(res: ApiResponse) {
    if (res.status === "success") {
        console.log(res.data)     // TS biết chắc: SuccessResponse
    } else {
        console.log(res.message)  // TS biết chắc: ErrorResponse
    }
}
💡
Bạn đã dùng pattern này trong AuthGuard! Khi viết if (!token), bạn đang narrow biến token từ string | null thành null trong if, và string bên ngoài!

Generics — Sức mạnh cốt lõi

🟣 MID-LEVEL

Generics cho phép viết code linh hoạt nhưng vẫn an toàn kiểu dữ liệu. Hãy nghĩ Generics giống "biến cho kiểu dữ liệu".

generics.ts
// VẤN ĐỀ: Phải viết lặp lại cho từng kiểu
function getFirstNumber(arr: number[]): number { return arr[0] }
function getFirstString(arr: string[]): string { return arr[0] }

// GIẢI PHÁP: Dùng Generic
function getFirst<T>(arr: T[]): T {
    return arr[0]
}

const num = getFirst([1, 2, 3])       // T = number → num là number
const str = getFirst(["a", "b"])     // T = string → str là string

// ====== Generic với Interface ======
interface ApiResponse<T> {
    status: number
    message: string
    data: T          // T sẽ thay đổi tùy API
}

// Dùng cho API login:
type LoginData = { access_token: string }
const loginRes: ApiResponse<LoginData> = {
    status: 200, message: "OK",
    data: { access_token: "eyJ..." }
}

// Dùng cho API lấy danh sách học sinh:
const studentsRes: ApiResponse<Student[]> = {
    status: 200, message: "OK",
    data: [{ id: 1, name: "An" }]
}
📌
Bạn đã gặp Generics trong dự án rồi! Trong loginService.ts: api.post<LoginResponse>('/login', ...) — Cái <LoginResponse> chính là Generic, nó bảo TypeScript: "API này trả về kiểu LoginResponse nhé!"

Class & OOP trong TypeScript

🟣 MID-LEVEL
class.ts
class Student {
    public fullName: string        // Ai cũng truy cập được
    private password: string      // Chỉ dùng trong class này
    protected grade: number      // Dùng trong class này + class con
    readonly id: number          // Chỉ đọc, không sửa được

    constructor(id: number, fullName: string, grade: number) {
        this.id = id
        this.fullName = fullName
        this.grade = grade
        this.password = "123456"
    }

    getInfo(): string {
        return `${this.fullName} - Lớp ${this.grade}`
    }
}

// Kế thừa
class HonorStudent extends Student {
    getInfo(): string {
        return `⭐ ${super.getInfo()} (Học sinh giỏi)`
    }
}

// Viết tắt constructor (TypeScript exclusive!)
class Course {
    constructor(
        public readonly id: number,
        public name: string,
        private maxStudents: number = 30
    ) {}
    // Không cần viết this.id = id... TS tự làm!
}
💡
Lưu ý cho React dev: Trong React hiện đại (2024+), gần như KHÔNG dùng Class. Thay vào đó dùng Function Component + Hooks. Nhưng biết OOP vẫn rất quan trọng để hiểu các thư viện bên dưới.

Module & Import/Export

🟡 SENIOR
Cấu trúc module trong dự án LMS
// ====== FILE: types/loginTypes.ts (XUẤT) ======
export type LoginFormData = {
    phoneNumber: string
    password: string
}

// ====== FILE: services/loginService.ts (NHẬP và DÙNG) ======
import type { LoginFormData } from '../types/loginTypes'
//      ↑ import type: Chỉ nhập kiểu (bị xóa sau compile)

// 1. Named export — Nhập phải đúng tên
export function AuthGuard() { /* ... */ }
// Nhập: import { AuthGuard } from '...'

// 2. Default export — Nhập tên gì cũng được
export default function App() { /* ... */ }
// Nhập: import App from '...'
// Hoặc: import MyApp from '...'
⚠️
import type vs import: Khi chỉ nhập kiểu dữ liệu (interface, type) mà không nhập giá trị hay hàm, hãy dùng import type { ... }. Nó sẽ bị xóa sạch khi build thành JS.

Async/Await & Promise

🟡 SENIOR

Nền tảng để gọi API. Mỗi lần giao tiếp với Backend đều dùng async/await.

async.ts
// Promise = "Tôi hứa sẽ trả kết quả cho bạn... nhưng chưa biết bao giờ."

// ====== async/await — LUÔN DÙNG CÁI NÀY! ======
async function login(phone: string, pass: string): Promise<LoginResponse> {
    try {
        const res = await api.post<LoginResponse>('/login', {
            phone_number: phone,
            password: pass
        })
        return res.data
    } catch (error) {
        console.log("Đăng nhập thất bại!", error)
        throw error
    }
}
//  ↑ async: Hàm này chứa thao tác BẤT ĐỒNG BỘ
//  ↑ await: ĐỢI cho xong rồi mới chạy dòng tiếp
//  ↑ Promise<LoginResponse>: Hứa trả về kiểu LoginResponse
//  ↑ try/catch: Bắt lỗi nếu API fail
💡
Giải thích bằng đời thực:
  • async = "Nhà bếp nấu nhiều món cùng lúc" (bất đồng bộ).
  • await = "Đợi món này xong rồi hãy bày ra bàn" (chờ kết quả).
  • try/catch = "Nếu món bị cháy thì xử lý thế nào" (bắt lỗi).

Utility Types (Built-in)

🟡 SENIOR

TypeScript cung cấp sẵn nhiều "công cụ biến hình kiểu dữ liệu". Tạo kiểu mới từ kiểu đã có mà không cần viết lại.

utility-types.ts
interface User {
    id: number; fullName: string; phone: string;
    role: string; isActive: boolean
}

// Partial<T> — Tất cả thuộc tính thành TÙY CHỌN
type UpdateUser = Partial<User>
// Dùng khi: Cập nhật user, chỉ gửi field thay đổi

// Required<T> — Tất cả thành BẮT BUỘC
type CompleteUser = Required<User>

// Pick<T, Keys> — CHỌN LẤY một vài thuộc tính
type UserPreview = Pick<User, "id" | "fullName">
// = { id: number; fullName: string }

// Omit<T, Keys> — BỎ ĐI một vài thuộc tính
type CreateUser = Omit<User, "id">
// Dùng khi: Tạo user mới (chưa có id)

// Record<K, V> — Tạo object với key/value cố định kiểu
type ScoreBoard = Record<string, number>
const scores: ScoreBoard = { "Toán": 9, "Lý": 8.5 }

// Readonly<T> — Không cho sửa bất kỳ thuộc tính nào
type FrozenUser = Readonly<User>

Advanced Patterns & Tricks

🔴 PRO

Conditional Types, Mapped Types & More

advanced.ts
// Conditional Type
type IsString<T> = T extends string ? "Yes" : "No"
type A = IsString<string>    // "Yes"
type B = IsString<number>    // "No"

// Mapped Types — Biến hình hàng loạt
type Nullable<T> = {
    [K in keyof T]: T[K] | null
}
interface Form { name: string; age: number }
type NullableForm = Nullable<Form>
// = { name: string | null; age: number | null }

// Template Literal Types
type EventName = `on${"Click" | "Hover" | "Focus"}`
// = "onClick" | "onHover" | "onFocus"

// satisfies — Kiểm tra kiểu mà KHÔNG mất inference
type Color = "red" | "green" | "blue"
const colors = {
    primary: "red",
    secondary: ["green", "blue"]
} satisfies Record<string, Color | Color[]>

assertion.ts
const input = document.getElementById("phone") as HTMLInputElement

interface ButtonProps {
    label: string                 // Bắt buộc
    onClick: () => void           // Bắt buộc: hàm callback
    variant?: "primary" | "danger" // Tùy chọn
    disabled?: boolean             // Tùy chọn
}

function Button({ label, onClick, variant = "primary", disabled }: ButtonProps) {
    return (
        <button onClick={onClick} disabled={disabled}
            className={`btn btn-${variant}`}>
            {label}
        </button>
    )
}

// Component với Children
interface CardProps {

    children: React.ReactNode  // Nhận bất kỳ thứ gì bọc bên trong

    return (
        <div className="card">
            <h3>{title}</h3>
            {children}
        </div>
    )
}

Gọi API với Type Safety

api-service.ts — Ví dụ thực tế từ dự án LMS
import { api } from '../../lib/axios'

// Bước 1: Kiểu cho Request
type LoginFormData = { phoneNumber: string; password: string }

// Bước 2: Kiểu cho Response
type LoginResponse = {
    access_token: string
    token_type: string
    must_change_password: boolean
}

// Bước 3: Viết hàm gọi API
export const authService = {
    async login(data: LoginFormData): Promise<LoginResponse> {
        const res = await api.post<LoginResponse>('/login', {
            phone_number: data.phoneNumber,
            password: data.password
        })
        return res.data
        // res.data.access_token  ✅ (TS biết là string)
        // res.data.xyz           ❌ (TS báo lỗi ngay!)
    }
}

Best Practices & Anti-Patterns

🔴 PRO

✅ NÊN LÀM (Best Practices)

best-practices.ts
// 1. ✅ Dùng "const" thay "let" khi giá trị không thay đổi
const MAX_STUDENTS = 30

// 2. ✅ Dùng "unknown" thay "any"
function processInput(input: unknown) {
    if (typeof input === "string") {
        console.log(input.toUpperCase())
    }
}

// 3. ✅ Dùng "as const" cho object/array cố định
const ROLES = ["student", "teacher", "admin"] as const

// 4. ✅ Discriminated Union cho state phức tạp
type LoadingState =
    | { status: "idle" }
    | { status: "loading" }
    | { status: "success"; data: string }
    | { status: "error"; error: string }

// 5. ✅ Tách type ra file riêng (types/xxx.ts)
// Giống cách bạn đã tổ chức trong dự án LMS!

❌ ĐỪNG LÀM (Anti-Patterns)

anti-patterns.ts
// 1. ❌ ĐỪNG dùng "any"
let data: any = fetchData()  // BAD! Mất hết bảo vệ

// 2. ❌ ĐỪNG ép kiểu bừa bãi
const user = {} as User     // BAD! Object rỗng không phải User

// 3. ❌ ĐỪNG dùng "!" khi không chắc chắn 100%
const el = document.querySelector(".maybe")!

// 4. ❌ ĐỪNG viết function trả kiểu any
function getData(): any { /* ... */ }

// 5. ❌ ĐỪNG bỏ qua lỗi bằng @ts-ignore
// @ts-ignore
const broken = "hello" * 5

// 6. ❌ ĐỪNG ghi kiểu thừa khi TS đã tự suy luận
const name: string = "An"   // THỪA!
const name = "An"             // ✅ Gọn hơn
